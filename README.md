# TraceOps

**Evidence-driven incident investigation and root-cause analysis.**

> **Status:** CP1.5 merged. GitHub CI and CodeQL pass for five incident scenarios, including recovery and evidence capture. A clean local-machine verification remains outstanding. No AI agent, cloud integrations, or automatic remediation yet.

TraceOps is an independent open-source Applied AI engineering project. The goal is to build an incident investigator that collects authorized evidence from logs, metrics, traces and code changes, tests competing root-cause hypotheses, and produces verifiable, cited diagnoses. It must abstain when evidence is insufficient.

We build it from first principles: **Build → Prove → Break → Harden → Extend**.

## Quick start (local, disposable environment only)

Prerequisites: Docker with Compose, `make`, Bash and curl. Node.js 22 is used by CI.

```bash
make up
make smoke
make integration  # exercises five incidents, request correlation, metrics & recovery
make down
```

```bash
curl http://localhost:3000/health/live
curl http://localhost:3000/health/ready
curl http://localhost:3000/orders/1
```

### Inject failures

```bash
make fault-db-down     # /orders/1 -> 503, /health/ready -> 503
make reset
make fault-slow        # /orders/1 takes ~2.5s
make reset
make fault-exception   # /orders/1 -> 500, database remains ready
make fault-upstream    # provider timeout -> 504, database remains ready
make fault-pool        # concurrent database-pool saturation -> some 503s
curl http://localhost:3000/metrics
make reset
```

**Do not expose this testbed publicly.** Fault injection and local credentials exist exclusively for an isolated development environment.

## What is included

- NestJS + PostgreSQL service with five deterministic incident scenarios
- Ground-truth incident manifest kept separate from future agent input
- Correlated structured JSON request events and Prometheus-style in-process metrics
- Local mock HTTP provider for genuine upstream timeout behavior
- Sanitized incident evidence fixtures generated by the integration suite
- Unit tests, HTTP smoke tests, fault-injection integration tests
- CI (typecheck, lint, tests, build, Compose validation, incident integration)
- CodeQL, Dependabot, contribution guidelines, issue/PR templates
- Checkpoint roadmap and architecture documentation

## Current validation limits

The starter was prepared without Docker or npm registry connectivity, so it has **not been independently run locally**. GitHub Actions subsequently passed typecheck, lint, tests, build, Compose, and five-scenario fault-injection checks on CP1.5 PR #8. The npm lockfile has been committed; GitHub CI and Docker now use reproducible `npm ci`.
