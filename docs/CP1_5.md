# CP1.5 — Observability and harder incidents

**Status:** Implementation candidate. Move to **Passed** only after five-scenario CI, CodeQL, and a clean local run succeed.

## Why this checkpoint exists

CP1 produced three obvious, reproducible faults. A useful future AI investigator needs:
- **Correlated** request and diagnostic events, not free-form console noise.
- **Machine-readable** measurements of latency, error rates, load and database pool pressure.
- **Overlapping symptoms** where a diagnosis requires discriminating evidence.
- **Replayable** sanitized evidence without access to the hidden incident labels.

We deliberately do **not** integrate AWS CloudWatch or start an LLM here. Vendor adapters arrive with CP8; CP2 can use the same contracts to read local evidence.

## Run locally

```bash
make up
make smoke
make integration
ls artifacts/evidence/*.json
make down
```

All services bind their application ports to localhost. The mock HTTP provider is accessible only on the Docker network.

## Five controlled scenarios

| Scenario | Command | Symptom | Discriminating evidence |
|---|---|---|---|
| DB disconnected | `make fault-db-down` | Order 503, readiness 503 | PostgreSQL can't be reached |
| Slow query | `make fault-slow` | Order ~2.5 s, status 200 | No pool-acquisition failure |
| App exception | `make fault-exception` | Order 500, readiness 200 | Application error, not dependency |
| Provider timeout | `make fault-upstream` | Order 504, readiness 200 | `UPSTREAM_TIMEOUT`, HTTP dependency |
| Pool saturation | `make fault-pool` | Concurrent slow orders and 503s | Two connections, acquire timeout, queue pressure |

The **slow query** and **pool saturation** cases both show elevated latency; distinguishing them requires additional evidence. The **DB outage** and **pool saturation** cases both produce 503 responses, but the latter occurs under contention with PostgreSQL still running.

## Request correlation

```bash
curl -i -H 'X-Request-ID: test-incident-001' http://localhost:3000/orders/1
docker compose logs --no-color api | grep 'request_completed'
```

A validated caller-supplied request ID is echoed as `X-Request-ID` and placed in a request-scoped asynchronous context. Invalid or oversized IDs are replaced with generated UUIDs.

Structured events use an allowlisted shape:

```json
{
  "timestamp": "2026-11-18T00:00:00.000Z",
  "level": "info",
  "service": "orders-api",
  "event": "request_completed",
  "request_id": "test-incident-001",
  "method": "GET",
  "route": "/orders/:id",
  "http_status": 200,
  "duration_ms": 12.3,
  "error_code": null
}
```

The example is a schema illustration, not a captured benchmark result. Raw query strings, order identifiers, request bodies, credentials, cookies, and IP addresses are never added to structured telemetry.

## Metrics

```bash
curl http://localhost:3000/metrics
```

Exports Prometheus-style counters/histograms and bounded database pool gauges:
- `traceops_http_requests_total` grouped by normalized route and status class.
- `traceops_http_request_duration_seconds` histogram (seconds).
- `traceops_db_pool_connections` gauges for total, idle, waiting and limit.

The testbed uses in-process counters. They intentionally reset on container restart. Live persistence, OpenTelemetry collectors and vendor backends will be introduced later when explicitly needed.

## Evidence capture and trust boundary

The integration script calls `scripts/export_evidence.py` **during each fault**, before restarting the service. It collects only structured, allowlisted fields from the local API and the exposed metrics. Output is written under the ignored path `artifacts/evidence/*.json`.

Ground truth is **separate**: `incidents/ground-truth.json`. Never load it into the future agent's context. CI uploads the five sanitized evidence files as an artifact to make investigation results inspectable.

## Hardening tests

- Correlation IDs are constrained to a safe format; route names have bounded cardinality.
- Error logs use stable codes, without interpolating exception messages.
- Metrics expose no credential, body, or customer dimension.
- Invalid log lines and unknown fields are dropped by the exporter.
- Each mode has a recovery path.
- Pool exhaustion must produce at least two 503s and one successful response under eight concurrent requests.
- Upstream timeout is a real aborted HTTP request to the local mock provider, not an arbitrary `sleep` in the controller.
- CI verifies all five cases and the exporter unit test.
